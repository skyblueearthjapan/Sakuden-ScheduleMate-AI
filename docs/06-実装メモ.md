# 実装メモ（本実装 = GPT-Live 版）

作成: 2026-09-14

## 構成（受付AIと同じ 2 段構え）

```
ブラウザ ──WebRTC 音声──► OpenAI GPT-Live (gpt-live-1)
   │ POST /api/voice/sessions (SDP offer)         ▲ sideband WebSocket（API キーはサーバーだけ）
   ▼                                              │
 server/index.mjs ────────────────────────────────┘
   │ delegation.created → 文字起こしの差分（この回に新しく言われた部分）
   ▼
 gpt-5.6-luna（Responses API, strict JSON Schema）= 判断担当
   { speak, thinking, pending_event, add_event, delete_event_id, set_lunch }
   │ add_event / delete_event → 所在ダッシュボード API（S006 櫻井会長）
   │ set_lunch → data/state.json
   ▼
 session.thinking.append + session.commentary.append → Live が音声で話す
```

| ファイル | 役割 |
|---|---|
| `server/index.mjs` | HTTP サーバー、静的配信、セッション作成/終了、`/api/state` |
| `server/live.mjs` | GPT-Live の作成と sideband（受付AI の gpt-live.ts の縮約） |
| `server/flow.mjs` | 委譲 → 判断 → 記録 → 返答。テストは偽の live を渡す |
| `server/agent.mjs` | Responses API 呼び出し（strict JSON） |
| `server/prompts.mjs` | Live の指示文・判断の規則・スキーマ・事実欄 |
| `server/dashboard.mjs` | ダッシュボード API クライアント（events の追加・削除） |
| `server/store.mjs` | お弁当の回答と音声利用時間（JSON ファイル） |
| `web/index.html` | 会話画面（マイク → WebRTC）・お弁当ボード。PWA（manifest / sw.js / アイコン） |

会話の規則: 予定は「こう登録しますね。よろしいですか」と聞いてから登録。返事は言葉だけ（ボタン無し）。
登録した日はお弁当を聞く（外出・休みなら「なしでよろしいですか」）。休みは聞かずに「なし」。

## 試験結果（2026-09-14、サンドボックスのダッシュボードに対して）

判断ロジック（GPT-Live なし、10 往復）: 登録・肯定・お弁当・休み→弁当なし・訂正（AじゃなくてB）・弁当あり・取り消し すべて正しく動作。
日付の解決: 「木曜」→ 9/17、「来週の月曜から水曜」→ 9/21〜9/23（連日）。

GPT-Live 通し（合成音声を擬似マイクへ、86 秒、約 $0.07）: 接続 → 挨拶 → 委譲 → 判断 → 音声で返答 → 終了まで成立。
実測で分かったこと:
- 委譲は発話の途中で起きることがある（「明日は和俊と菱和産業」で 1 回目、「朝から行く」が次の回に回った）。判断側は累積の文字起こしを見るので破綻しない。
- Live のつなぎ「はい、少々お待ちください」は毎回入る。
- 会長の delta とさくらの delta は交互に届くので、字幕は話者ごとにターンを続ける（修正済み）。

## 画面（2026-09-14 改訂）

- 会話は流れる chat ではなく、受付AIと同じ「写真が動かず、いまの一言だけが差し替わる」形。さくらの最新の発話は写真の上の吹き出し、会長の最新の発話はその下に 1 行。
- スマホ（〜899px）: 上に写真（高さ 44dvh）、下にタグ・会長の一言・マイク。下タブで「お弁当」ボードへ。
- PC（900px〜）: 写真を左に大きく（幅 52%）、右に会話とお弁当ボードを縦に並べる。タブ無し。
- 会話前は吹き出しに「おはようございます、会長。今日は…」と状況を出す（`/api/state` から）。

## アクセスキー（2026-09-14 追加。手順書 3 章）

- `server/access.mjs`: `APP_ACCESS_KEYS="ラベル:キー,…"`、cookie `ssm_key` → ヘッダ `x-app-key` の順、`timingSafeEqual` で全走査。
- `POST /api/key` → 200 + cookie（400 日、HttpOnly/Secure/SameSite=Lax）。`GET /api/me` → `{label}`。
- `/api/health` と `/api/key` 以外の `/api/*` はキー必須（未設定 503、無効 401）。クエリ文字列のキーは受け付けない。
- 全応答に `X-Content-Type-Options: nosniff` / `Referrer-Policy: no-referrer` / `X-Frame-Options: DENY` / CSP（Google Fonts のみ許可）。
- 画面は `#k=` を localStorage に保存し `X-App-Key` を付ける。401/503 は「このリンクからは使えません」の全画面で止める。
- ローカル試験: 未設定 503、無効 401、cookie 発行、ヘッダ受理、クエリ不可、画面の案内表示と `#k=` からの起動を確認済み。
