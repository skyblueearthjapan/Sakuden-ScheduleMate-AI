# 会話型スケジュールAI 設計案（シンプル構成・会長限定）

作成日: 2026-09-14
目的: **櫻井会長（staff S006）限定**。会話で予定とお弁当の要否を聞き取り、予定は所在ダッシュボードの DB に反映する。**できるだけ単純に作る。**

2026-09-14 更新: 会長限定に絞り、お弁当の確認とお弁当ボードを追加。画面は「会話」「お弁当」の 2 つだけ（設定・履歴・予定一覧は持たない）。本番 DB の確認結果は `04-本番DB確認-2026-09-14.md`。

## 1. 全体像

```
利用者 ──チャット画面(1 ページの HTML)──► schedule-ai (FastAPI 1 ファイル)
                                              │
                                              ├─ Claude API（会話 + 予定の抽出、ツール呼び出し）
                                              │
                                              └─ 所在ダッシュボード API（既存・無改修）
                                                   GET  /api/staff                 名簿と既存予定
                                                   POST /api/staff/{id}/events     予定の追加
                                                   DELETE /api/staff/{id}/events/{eid}  予定の削除
```

- サーバーは **Python ファイル 1 つ**（`app.py`）+ HTML 1 つ（`index.html`）。DB は **お弁当の要否だけ** 小さな SQLite に持つ（予定はダッシュボードが正本）。
- 予定の正本はダッシュボードの SQLite。AI 側はダッシュボードの HTTP API を叩くだけ。
- 直接 SQLite に書かない（SSE 通知が飛ばず画面が更新されないため）。

## 2. 会話の流れ

1. 利用者が「明日 10 時に A 社訪問」のように入力する
2. Claude がツール `list_staff` で名簿を取り、誰の予定か特定する（本人名をチャット冒頭で選ぶ方式が最も単純）
3. Claude がツール `list_events` でその人の予定を読み、「〇月〇日 10:00 A社訪問（訪問）で登録しますか？」と確認する
4. 利用者が「はい」→ ツール `add_event` → ダッシュボードに即反映（SSE で全画面更新）
5. 「取り消して」→ `delete_event`

ツールは 5 つ（list_events / add_event / delete_event / set_lunch / get_lunch）。相手は会長固定なので名簿ツールは要らない。予定の変更は削除＋追加で済ませる。

お弁当: 予定を登録した流れで「その日のお弁当はいる／いらない」を聞く（外出・休みなら「なしでよいですか」と提案）。前日 15:00 までに未回答なら AI から聞く。

## 3. 予定として扱う項目（ダッシュボードの EventIn と同じ）

| 項目 | 例 | 備考 |
|---|---|---|
| date | 2026-09-15 | 必須 |
| endDate | 2026-09-16 | 連日のときだけ |
| title | A社 訪問 | 必須、120 文字まで |
| time | 10:00 | 任意 |
| kind | 訪問 / 工事 / 社内 / 休み / その他 | AI が文脈から選ぶ |

## 4. 人物画像

- ダッシュボードのスタッフに画像は無い（`Avatar.jsx` はイニシャル表示）。
- チャット画面で相手のアイコンや AI アシスタントの顔を出す場合、受付AIの `tools/codex-image` を流用して **GPT-Image で架空の人物画像を生成**する。
- 生成先: `web/assets/avatars/{staff_id}.png`。manifest に人物ごとのプロンプトを書く。実在人物は使わない。

## 5. ファイル構成（予定）

```
Sakuden-ScheduleMate-AI/
├ app.py            FastAPI: /chat（Claude 呼び出し + ツール実行）, / で index.html を返す
├ index.html        チャット UI（素の HTML + fetch。ビルド不要）
├ requirements.txt  fastapi, uvicorn, httpx, anthropic
├ .env.example      ANTHROPIC_API_KEY, DASHBOARD_API_BASE（例: http://sd-web/api）
├ tools/codex-image/  受付AIから流用（人物画像生成）
└ docs/
```

## 6. 決めておくこと

- 会話の入口は **テキストチャット**から始める（音声は後から GPT-Live か Web Speech API で足せる）
- ダッシュボード API には認証が無いため、同じ Docker ネットワークに同居させるか Tailscale 内からだけ叩く
- 予定を書く前に必ず利用者へ確認する（受付AIと同じ「推測で書かない」規則）
